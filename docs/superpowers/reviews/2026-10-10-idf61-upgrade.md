# 评审：ESP-IDF v5.5.4 → v6.1.0 升级（2026-10-10）

> 设计 `specs/2026-10-10-idf61-upgrade.md` / 计划 `plans/2026-10-10-idf61-upgrade.md`

## 现象

用户要求把项目 IDF 基线升级到 6.1。直接切换环境后连续出现 6 类失败：
① `idf.py` 启动即崩溃（组件管理器读 `ESP_IDF_VERSION` 得 None）；
② CMake 报 `Failed to resolve component 'json'`；
③ `esp_vfs_usb_serial_jtag.h: No such file or directory`；
④ 三个头文件 `[-Werror=header-guard]`（保护宏 `#ifndef`/`#define` 名字不一致）；
⑤ `uart_config_t` `[-Werror=missing-field-initializers]` + designator 顺序错误；
⑥ 测试宿主 `EXTRA_COMPONENT_DIRS doesn't exist: tools/unit-test-app/components`。

## 根因（逐条，均已对照 v6.1 源码/迁移指引核实）

1. **ESP_IDF_VERSION**：v6.1 的组件管理器 `idf_extensions.py:388` 用
   `Version.coerce(os.getenv('ESP_IDF_VERSION'))` 判版本；官方 `activate.py` 会设置该变量，
   `build.sh` 手工导出环境没有 → TypeError。v5.5.4 的组件管理器不读它，所以旧脚本没暴露。
2. **json 组件移除**：官方迁移指引 `release-6.x/6.0/protocols.rst`——内置 `json` 组件
   已删，cJSON 改走组件管理器 `espressif/cjson`（API 不变，`#include <cJSON.h>` 照旧）。
3. **USB-Serial-JTAG VFS API 删除**：`release-6.x/6.0/storage.rst`——`esp_vfs_dev_usb_serial_jtag_*`
   已删，改用驱动新 API `usb_serial_jtag_vfs_*`（头文件 `driver/usb_serial_jtag_vfs.h`，
   组件 `esp_driver_usb_serial_jtag`）。UART 侧行结尾同理改名
   `esp_vfs_dev_uart_port_set_*` → `uart_vfs_dev_port_set_*`。
4. **header-guard 严查**：v6.1 编译参数收紧，历史遗留的三个保护宏不一致
   （`_APPLICATION_H_` vs `_APPLICATION_H__` 等）从"容忍"变 `-Werror`。
5. **uart_config_t 加字段**：v6 新增 `rx_flow_ctrl_thresh`、`rx_glitch_filt_thresh`、`flags`
   且字段顺序为 flow_ctrl → 两个 thresh → source_clk → flags；指定初始化器缺项触发
   `-Werror=missing-field-initializers`。**置 0 与原缺省值初始化完全等价**（v6.1 `uart.c`
   对 0 的处理：关闭毛刺滤波、RTS 阈值不启用）。
6. **unit-test-app 移除**：v6 删了 `tools/unit-test-app`；unity 已是内置标准组件
   （`components/unity`），`PRIV_REQUIRES unity` 可直接解析，无需 EXTRA_COMPONENT_DIRS。
7. **driver 兼容组件缩水**（升级前就预判到）：v6 `components/driver` 只剩 i2c/touch/twai，
   `esp_driver_gpio` 是其 PRIV_REQUIRES 不传递头文件路径、不含 esp_driver_uart
   → `REQUIRES driver` 必须改为显式 `esp_driver_uart esp_driver_gpio`（include 路径不变）。

## 验证证据

1. **编译**：`bash scripts/build.sh s3` → `Project build complete`；`lucky-page.bin` 1.93MB
   （ota_0 3MB 剩 38%），bootloader/分区表/assets.bin 齐全；无废弃/迁移告警。
2. **sdkconfig 迁移**：`CONFIG_IDF_INIT_VERSION` 5.5.4→**6.1.0**；Octal PSRAM / 16MB Flash /
   自定义分区表 / USB-Serial-JTAG 控制台全部保留。
3. **测试宿主编译**：`test_apps` v6.1 全新构建 → `Project build complete`。
4. **片上单测**（真机，`LUCKY_PORT=/dev/cu.usbmodem1423101`）：**240 PASSED, 0 FAILED**，
   单次启动无重启。
5. **真机回归**（按纪律单测后整包烧回主固件）：启动日志 `ESP-IDF: v6.1`，7 个初始化阶段
   全过——NVS 现场配置保留（pages=30 speed=60 等）、SPIFFS 3.3MB 挂载、DMX/打印机 UART2
   就绪、归零序列下发、AP `lucky-page-0E6D` 启动（192.168.4.1）。无崩溃无重启循环。
6. **待真机回归项**（设备在工位即可补跑）：`api_verify.py` HTTP 验收、`web_smoke.py` 冒烟、
   串口 `psample` 实票打印（本轮工具链升级未触碰渲染/HTTP 逻辑，风险低）。

## 教训（沉淀给后续升级）

- 手工导出 IDF 环境的脚本，升级时要 diff 官方 `activate.py` 新增了哪些环境变量
  （本次 `ESP_IDF_VERSION` 就是官方流程有、手工脚本没有的隐式契约）。
- 头文件保护宏这种"历史带病生存"问题，会在编译器收紧时集中爆雷；扫描脚本
  （ifndef/define 比对）已随本次验证全库清零，可作为后续 CI 检查。
- v6 的 `uart_config_t` 等结构体加字段后，指定初始化器**必须按声明顺序**且**全字段覆盖**，
  否则两个 -Werror 同时报。
