# 评审：复位手势可信性闸门（应对"无人接触却复位"）

> 关联：`specs/2026-10-10-reset-button.md`（恢复按钮本身）、`reviews/2026-10-10-reset-button.md`（首轮取证）

## 现象（真机，2026-10-11 13:11:30）

设备**无人接触**的情况下执行了一次网络复位：NVS 铁证 `net_rst_cnt 0→1`、
`net_rst_epoch=1791695490`，同批清空 `wifi_list/wifi_ssid/ap_pass` → 设备掉成 AP-only。

**已排除的路径**（逐条给证据，避免再次误判）：

| 候选 | 排除依据 |
|---|---|
| 我的脚本 | `api_verify` / `web_smoke` / 离线校验里**没有**任何清空网络的调用（只有 `{"index":99}` 越界负例 → 400） |
| 重启/上电路径 | 连做 **3 次硬复位**，计数稳定停在 1、配置完好；开机守卫（30 s）也在位 |
| 串口 `wifi resetnet` | 该时段只发过 `btbtn` 与状态查询；且复位日志现在带**来源标记**可区分 |
| HTTP 接口 | 遍历 `web_server.cc`，**没有**任何 handler 调用复位函数（只有 Settings 的字段写入） |
| 用户手动长按 | **用户确认当时没有接触板子/GPIO5** |
| GPIO5 空闲噪声 | `rstbtn` 当前电平=1（上拉正常）；此前 `rstmon 180` 秒监视：**0 次跳变、0 个下降沿** |

⇒ 剩余唯一嫌疑：**驱动层误报长按事件**（`esp_button` 状态机异常 / 极短电平扰动被积分成"持续按下"）。
该路径无法从代码侧证伪，于是改为**让它在结果上不可能发生**。

## 修法：三条证据缺一不可（纯逻辑 + 单测）

新增 `main/reset_gesture.{h,cc}`（纯函数 `DecideResetGesture`），复位前必须同时满足：

1. **我们亲眼见过按下事件**（`PRESS_DOWN` 由我们自己记录时刻），且它发生在约 `long_ms` 之前
   —— 幽灵长按事件**不会**先发 `PRESS_DOWN`，这条直接封死纯驱动误报；
2. **引脚此刻确为低电平**，且连续 **8 次 × 10 ms 采样全部为低**
   —— 挡掉"事件为真但电平已回弹"的时序错位；
3. **已过开机 30 秒守卫**（原有条件保留）。

任一不满足 → **拒绝复位**，并打**显眼错误日志**（含开机毫秒、按下事件时刻、低电平采样数），
同时累加 `幽灵长按拒绝次数`（`rstbtn` 可读）—— 这条日志就是下次复发的现场线索。

另外给复位日志加了**来源标记**：`恢复网络默认配置（来源：恢复按钮长按 5 秒 / 串口 wifi resetnet）`，
事后取证不必再猜是哪条入口。

## 追加：GPIO5 "引脚黑匣子"（常驻取证）

闸门只能"拦"，还需要"证"。因此加了一个 10 ms 周期的常驻采样（`esp_timer` 任务上下文，
只做读电平 + 计数，开销可忽略）：

- **每一次电平跳变都打 `W App` 日志**（含开机毫秒、累计跳变次数、累计低电平毫秒）；
- `rstbtn` 显示：`累计跳变 N 次 / 累计低电平 X ms / 最近跳变时刻 / 当前电平`。

价值：下次若再出现"无人接触却复位"，**无需再靠推断**——
- 跳变=0 且低电平=0 → 引脚从未被拉低 ⇒ 一定是软件/驱动侧问题，且闸门已挡住；
- 跳变>0 / 低电平≈5000 ms → **引脚真的被拉低了 5 秒** ⇒ 电气/接触/干扰问题，
  日志里有精确时刻，可对着现场（谁动了什么、附近什么信号在切换）复盘。

## 仍在进行：长时现场录制

已开启后台串口录制（1 小时，`/tmp/reset_soak.log`），只落盘关键行
（`恢复按钮*` / `恢复网络默认配置*` / `幽灵长按*` / `boot:` / `Guru` / `panic`）。
若再次发生：① 有来源标记 → 立刻知道入口；② 若是幽灵长按 → 有显眼的 `E App` 拒绝日志 + 计数；
③ 若通过判定真复位了 → 说明是**真实电平**被拉低（那就是硬件侧：线缆/接触/电源），
届时可据 `rstmon` 与采样日志继续定位。

## 诚实边界

本次**没有找到确定根因**（无接触、无命令、电平稳定、三连复位不复现）。已把"不可解释的复位"
从"可能悄悄发生"变成"要么不可能发生，要么留下显眼日志与计数"。若用户不能接受这一残余风险，
可选加固：**双动作确认**（长按松开后再长按一次才复位）—— 需用户确认（此前选择的是保持单手势）。
