# 评审：6 个 HTML 页面的设计现状（重设计前）

> 输入：`main/assets/spiffs_contents/` 下 6 页 + `app.css` + `app.js`
> 结论：**功能信息齐全，但"设计语言"只到组件级别，缺页面级的骨架、层级与反馈**。

## 1. 功能与意图（先理解，再动手）

| 页面 | 用户任务（意图） | 关键信息 | 关键动作 |
|---|---|---|---|
| `index.html` 抽奖 | 现场一键开奖、随时知道"能不能抽/抽到了什么" | 状态、最近结果、累计/今日 | 抽奖、打印测试票 |
| `prizes.html` 奖池 | 配总页数/概率/库存，并看懂概率 | 每级页码、权重、**概率%**、库存/剩余 | 增删级、保存、重置库存 |
| `receipt.html` 小票 | 拖拽排版小票，所见即所打 | 画布、元素属性、插入参数 | 保存/预览/打测试页/缩放 |
| `logo.html` Logo | 上传图片→看二值化效果→写入设备 | 当前 logo 尺寸/字节/耗时 | 上传、删除 |
| `calibrate.html` 标定 | **微调偏移→点动→眼睛确认**闭环 | 当前页/基础/偏移/实际 | ±微调、翻页/跳页、清零 |
| `wifi.html` 网络 | 换网络、改热点、排障 | AP 名/密码状态、STA IP/信号/已连 | 扫描连接、断开/重连、静态 IP |

**贯穿性意图**：这是**现场设备**的控制台 —— 使用者常站在机器旁用手机操作，
一次只做一件事，最怕"点了没反应""不知道当前状态""误触破坏性操作"。

## 2. 问题清单（按严重度）

### P0 语义冲突与误触风险
1. **一个红色兼任 4 种语义**：主操作（`--p`）、选中态（`nav a.on`）、故障（`.fault` 边框）、
   低概率警示（`.prob.low`）、删除链接（`#e74`）。用户无法从颜色判断"这是好事还是危险"。
2. **破坏性操作没有统一形态**：「清零全部偏移」「删除 Logo」「重置库存」「清除所有已保存 WiFi」
   各自长得不一样，有的 `confirm()`、有的直接执行（`deleteLogoInline()` 无确认）。
3. **成功反馈太弱**：保存成功只是卡片底部一行 `.warn` 变 `.ok` 的 12px 小字，
   手机上一滑就看不见 → 用户重复点击。

### P1 层级与一致性
4. **页面标题三种写法**：`h1`（wifi）/ `<b>`（prizes、logo）/ 无（index、calibrate、receipt）。
5. **卡片没有"头"**：标题直接用 `<b>`/`<h3>` 贴在内容上；wifi 页独有 `.card-title` 下边框。
6. **提示样式四套并存**：`.note` / `.hint` / `.info`（logo 页自定义）/ `.warn` / `.ok`。
7. **表单控件被页面内联覆盖**：`prizes.html` 的 `<select>` 自带 `background/#0d1b3e、
   padding:5px、radius:4px`，与基础层 8px/10px 不一致。
8. **按钮只有 3 档**（默认/primary/mini），无 danger/ghost/loading；`wifi.html` 另造 `.action-btn`。

### P2 信息密度与可扫读性
9. **没有"状态条/指标条"**：index 的累计/今日、calibrate 的四个数值、wifi 的九行状态，
   视觉形态各不相同，无法形成"看顶部就知道现状"的习惯。
10. **概率列最该突出却最弱**：奖池页 `概率` 只是 11px 小字，没有条形可视化。
11. **空状态缺失**：只有 wifi 有 `.empty-hint`；index 的"最近结果"为空时是一片空白。

### P3 可访问性
12. **对比度不足**：`--tx-mute #789` on `--bg #1a1a2e` ≈ 3.0:1（正文级建议 ≥4.5:1）。
13. **删除用 `<a href="#">`** 而非按钮（键盘不可聚焦、语义错误）。
14. **无 `:focus-visible`** 焦点环；`aria-current` 未标当前页。

## 3. 设计约束（来自既有校验脚本，必须保留）
- 内容宽度 **760px**（`receipt.html` 例外 `body.wide`）；
- 卡片 `padding 16px / radius 12px`、按钮 `8×16 / 14px / radius 8`、输入 `8×10 / 14px / radius 8`；
- 6 页 nav 文案序列一致 + `nav a.on` 底色一致；手机端触控 ≥44px、输入 ≥16px；
- wifi 页 artnet 结构（状态行/卡片标题下边框/通栏主操作/页标题）；
- 奖池表格手机端转卡片（`td::before` 标签）；画布拖动量纲 `colw=14 / lineh=22`。

## 4. 重设计方向（摘要，详见 spec）
**"设备控制台"**：页头（标题+一句说明+状态 chip）→ 指标条 → 分区卡片（带头部与右侧动作）
→ 内容 → 底部操作栏；颜色按**语义**分配（brand/success/warn/danger/info 五色分离），
破坏性操作统一进「危险区」并二次确认；反馈改为**带色条的消息条 + 成功 toast**。
