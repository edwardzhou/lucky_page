# 评审 41：SD 卡能力（从 dms-pager 移植，SPI 模式）

日期：2026-10-28 · 结果：通过（真机插卡验证）

## 现象（需求）

从 `~/esp32_work/dms-pager` 导入 SD 卡能力；用户指定引脚
**MISO=G13 / SCK=G14 / MOSI=G21 / CS=G47**；范围 = 文件管理 + 素材优先存 SD。

## 实现（优先用 ESP-IDF 组件）

- **不搬 dms-pager 的后端抽象**，直接用 IDF：`esp_vfs_fat_sdspi_mount` +
  `sdspi_device_config_t` + `SPI_DMA_CH_AUTO` + FATFS（`f_getfree`）；S3 只用 SPI 模式。
- `main/storage/sd_card.{h,cc}`：延迟 1s 挂载、3 次重试、失败只打日志（规则 7）、
  容量查询、卡名摘要、手动挂载/卸载；挂载失败绝不 abort。
- `main/storage/sd_paths.{h,cc}`：路径规范化/防穿越、素材与音效固定路径、文件名校验（纯函数+单测）。
- **素材分层存储**：`asset_store` / `sound_store` 读写优先 SD
  （`/sdcard/lucky/assets/<id>.lgo`、`/sdcard/lucky/sounds/<role>.pcm`）；
  未挂载或 SD 读失败回落 flash 槽；删除两处都清。
- **Web 文件管理**：`/api/sdcard`（状态/容量）、`/api/sdcard/list|upload|download|file|rename|mkdir|mount|unmount`，
  路径全部经 `sd_paths::Full` 限制在 `/sdcard` 内。
- **UI**：第 9 页 `sdcard.html`：状态卡（卡名/容量/进度条/挂载卸载）、面包屑、文件表
  （目录优先）、上传（多选）、下载、重命名、删除、新建文件夹。

## 真机踩坑

1. **SD 写入成功后调用 `Erase()` 清 flash 旧副本，把刚写进 SD 的文件也删了**
   → 表现：上传成功但列表回落 flash。修法：拆出只清 flash 的 `ClearFlashSlot/ClearFlashRole`。
2. **删除素材留下悬空页面引用** → `pages.html` 请求 `/api/assets/raw` 404。
   修法：删除素材时同步把 `page_content` 中引用置 -1 并落盘。
3. **测试宿主缺 SD 依赖**：`asset_store.cc` 引入 `storage/sd_card.h` 后测试宿主编译失败
   （缺 `driver/sdmmc_types.h`）。修法：test_apps 增加 `sdmmc fatfs esp_driver_spi`
   依赖并编译 `sd_card.cc`（不在 app_main 初始化，不会碰卡）。
4. **单测后未烧回主固件**导致设备 HTTP 不可达（老坑，规则 §五）。
5. **布局检查端口 8898 被并行子任务占用** → bind 失败；串行执行即可。

## 验证证据（真机，卡：SU01G 0.9GB）

- 挂载：`/api/sdcard` 返回 `mounted=true`、总容量 987,283,456B、可用 950,083,584B。
- 文件管理全链路：mkdir → upload（16B 文本）→ list → rename → download（内容一致）→
  delete 文件/目录；路径穿越 `/../../etc` → **400**。
- 素材存 SD：上传音效 1.0s → `/sdcard/lucky/sounds/win.pcm`（48,000B），接口显示 custom；
  上传图片 → `/sdcard/lucky/assets/0.lgo`（+ `.name` 侧车）；删除后两处清空。
- 回落：卸载 SD → 上传图片成功落 **flash 槽**；重新挂载后仍能读到（SD 优先、缺失回落 flash）。
- 单测 **320 PASSED / 0 FAILED**（新增 SD 路径 5 项）；布局 **102/102**（9 页）；
  冒烟 **40/40**（9 页，零 JS 异常）；`api_verify` **84/84**。

## 续：中文文件名与长路径（同日第二轮）

现象：卡上原有中文名显示乱码；新建中文目录 500；长中文路径 414/500。

根因与修法：
1. **FATFS codepage=437**（ASCII）无法表示中文 → 切 **CP936（GBK）**，
   与 dms-pager 卡上的文件名一致；`sdkconfig` + `sdkconfig.defaults` 同步。
2. Web 层是 UTF-8、VFS 是 GBK → 新增 `storage/sd_name_codec`（UTF-8↔GBK，
   复用 GBK 表；GBK→Unicode 用按码排序的二分表），在 SD 边界逐段转换；
   文件名/目录名全部经过它，列表回显用 `FromFs`。
3. **QueryValue 固定 96 字节** + 查询串 160 字节会截断长中文路径 → 改动态长度
   （按 `httpd_req_get_url_query_len` 分配）。
4. **CONFIG_HTTPD_MAX_URI_LEN=256** → 长中文路径 414；提到 **1024**
   （并在 `config.max_uri_len` 同步设置）。
5. **mkdir 非幂等**：已存在返回 500 → 改为 EEXIST 视为成功（幂等）。

验证（真机）：
- 新建 23 个汉字的目录 → 上传「测试文件.txt」→ 列表/下载（内容一致）→
  重命名「改名后.txt」→ 删除文件/目录，全部成功；卡上原有「4单元_dmx_pt.xlsm」
  正确显示中文。
- 卸载 → 重新挂载 → 目录 18 项正常、上传/删除正常（复测无异常）。
