# 设计：支持用户修改本机热点（AP）密码

> 日期：2026-10-10　|　状态：已评审（用户要求"WiFi AP 密码，支持用户修改"）
> 关联：`specs/2026-10-10-wifi-artnet.md`（AP 改名已做，本次补密码）

## 1. 现状与问题

AP 密码硬编码在 `wifi_manager.cc` 的 `kApPass = "12345678"`（三处引用：启动配置、启动日志、
串口状态打印）。用户无法修改 —— 现场（展会/店铺）希望改成自己的密码。

## 2. 目标与约束

1. 用户可在 WiFi 页改 AP 密码，立即生效，**重启后仍然生效**（持久化）。
2. **密码绝不回显**（强制规则 9）：接口只回 `ap_pass_custom` 布尔；
   页面只显示"默认 12345678"或"已自定义（不显示）"。
3. **不能把自己锁在外面**：AP 密码错误只影响连热点，STA 连接与抽奖不受影响；
   忘记密码时的救援通道是**串口**（物理接触）—— `wifi` 命令打印当前 AP 密码。
4. 校验：WPA2 要求 **8..63 字节**、无控制字符；空串 = **复原默认**（与 AP 改名的"空串=复原"一致）。
5. 降级不 abort：应用失败只记日志。

## 3. 设计

### 3.1 纯函数（`wifi_config.{h,cc}`，可上单测宿主）
```cpp
/// 校验 AP 密码：8..63 字节、无控制字符。返回空串 = 通过。
std::string ValidateApPassword(const std::string& pass);
```

### 3.2 Settings
| key | 类型 | 默认 | 含义 |
|---|---|---|---|
| `ap_pass` | string | "" | 自定义热点密码；空 = 用默认 `12345678` |

### 3.3 wifi_manager
- 启动时：`WifiApPassword()` = Settings 有值且合法 ? 该值 : `kApPass`（默认）；
  `authmode` = 有密码时 `WIFI_AUTH_WPA_WPA2_PSK`。
- 新增 `bool SetApPassword(const std::string& pass, std::string* error)`：
  空串 → 清 Settings + 用默认密码；否则校验 → 存 Settings → 立即
  `esp_wifi_set_config(WIFI_IF_AP)`（保留 SSID/信道 0/最大连接数 + 设 authmode）。
- 新增 `std::string ApPasswordForConsole()`：**仅供串口打印**（物理接触的救援通道；
  HTTP 层绝不调用）。

### 3.4 HTTP（**不加路由**，扩展已有 `PUT /api/wifi/ap`）
- 请求体支持 `ap_ssid` 和/或 `ap_pass`，至少一个；各自独立校验，任一失败回 400（带原因）。
- 空串语义：`ap_ssid:""` = 复原默认热点名；`ap_pass:""` = 复原默认密码。
- `GET /api/wifi` 增加 `ap_pass_custom`（布尔，**绝不回密码**）。

### 3.5 前端（沿用 artnet 风格布局）
- 状态行「AP 密码」：`默认 12345678` / `已自定义（不显示）`，带「修改」小按钮。
- 内联编辑区：新增密码输入框（`type=password`）+ 保存 / 复原默认 / 取消，
  提示"至少 8 位；修改后已连接热点的手机需重连"。
- 页脚提示文案随状态变化（不能写死 12345678）。

### 3.6 串口
- `wifi` 状态打印真实 AP 密码（救援通道）；`wifi ap <名>` 保持只改名；
  新增 `wifi appass <密码>`（空 = 复原默认）。

## 4. 测试与验证

| 层级 | 内容 |
|---|---|
| 单测 | `ValidateApPassword`：合法 8/63 位、7 位拒绝、64 位拒绝、控制字符拒绝、中文按字节计 |
| HTTP | 改密码 → 200；`GET /api/wifi` 的 `ap_pass_custom=true` 且**响应全文不含新密码字符串**（明文泄露断言）；复原默认 → `ap_pass_custom=false`；负例（7 位/64 位/控制字符/空对象 → 400）|
| 设备 | 改密码后用**串口** `wifi` 复核生效值 = 新密码；`httptest GET /api/wifi` 确认不泄露；复原默认；核对热点仍在广播、STA 与抽奖不受影响 |
| 前端 | 离线：密码行/按钮/输入框存在、保存走通、状态显示"已自定义"；真机：`ap_pass_custom` 显示正确、GET 响应无密码 |
| 数据 | 结束时恢复默认密码、AP 名、DHCP、已保存网络、模板/偏移不变 |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户忘记自定义密码 → 连不上热点 | 串口 `wifi` 打印真实密码（物理通道）；页面明示"忘记可串口查看或复原默认"；**热点不会消失**，STA/抽奖不受影响 |
| 密码明文经 HTTP 回显 | 接口只回布尔；断言"响应体不含新密码"；页面只显示"已自定义（不显示）" |
| 改密码把已连热点的手机踢掉 | UI 明确提示需重连；只影响 AP 接口 |
| 空串误设成开放网络 | 空串定义为**复原默认**（非开放）；`authmode` 始终 WPA2 |
