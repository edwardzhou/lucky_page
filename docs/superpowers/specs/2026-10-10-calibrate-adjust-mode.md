# 设计：标定页学习 page-player 的「页码调整模式」

> 日期：2026-10-10　|　状态：已评审（用户已确认：**调整模式为默认 + 折叠保留高级表格**、**加跳页输入**）
> 参考实现：`~/esp32_work/page-player`（`tab-adjust.html` + `docs/plans/2026-04-11-req0018-page-adjust-design.md`）

## 1. 参考模式的本质（要学的是什么）

page-player 的「行程微调」把标定从"填表"变成**边调边看**：

| 要素 | 行为 |
|---|---|
| 状态卡 | 实时显示 **基础值 / 偏移 / 实际值 / 当前页** |
| 微调按钮 | `+10/+5/+1` `-1/-5/-10` —— **只改偏移、立即落盘、不翻页** |
| 翻页导航 | 上页 / 下页 / 首页 —— 触发**真实翻页**，用眼睛确认落页 |
| 清零 | 清零当前（本机）/ 清零全部 |
| 数据模型 | **基础映射 + 每页偏移分离**：实际值 = `clamp(base + offset, 0, 255)`，偏移 0 = 未调整 |
| 使用说明 | 页内给出操作步骤 |

核心价值：**改的值与看到的落页在同一屏内闭环**，且偏移与基础映射互不污染（可随时清零回到理论值）。

## 2. lucky-page 现状与差距（已实测确认）

**已就绪（后端）**
- `main/page_adjust.{h,cc}` 已是同款偏移模型（每 cell 每页 `int8_t`、SPIFFS JSON、`clamp 0..255`）
- 已接进启动：`application.cc` 里 `LoadAdjust()` + `Resize(1, pages)`
- **点动已叠加偏移**：`Application::DirectDrive()` 用 `GetAdjustedValue(0, page)` →
  微调后点动能看到效果（闭环的前半段已通）
- `GET /api/pages` **已返回真实映射 `values`**（不是公式猜的）
- `PageAdjust::Resize()` 只增删长度、**不清已有偏移**

**缺口**
1. **偏移没有 HTTP 接口**：只有 `PUT /api/page-mapping`（整表写绝对映射），
   无法读改单个偏移 → 界面上没法做调整模式。
2. **界面是"填表"不是"调整"**：`calibrate.html` 是 30 行绝对行程值表格 + 每行点动，
   没有状态卡、没有 ± 微调、没有上页/下页/跳页、没有清零；且**初始值用公式猜**
   （`lo + i*(hi-lo)/(n-1)`），保存时会把猜的值整表覆盖真实映射 —— **隐患**。
3. **设备 `current_page` 不可用于标定**：只有归零路径写它，`DirectDrive`（点动）**不更新**
   → 调整模式的"当前页"必须用**界面本地游标**。

## 3. 方案

### 3.1 后端：新增 3 个接口（`web_server.{h,cc}`）

全部经 `MainSync` 走主线程（与既有 `PUT /api/page-mapping` 一致），改完**立即落盘**（SPIFFS 文件极小，掉电不丢）。

| 方法 | 路径 | 请求 | 响应 | 校验（失败一律 400/409，明确原因） |
|---|---|---|---|---|
| GET | `/api/adjust` | – | `{cell_count:1, total_pages, offsets:[[..]], mapping:[..]}` | – |
| PUT | `/api/adjust` | `{cell:0, page:int, offset:int}` | `{ok, cell, page, offset, base, value}` | 坏 JSON→400；`cell!=0`→400；`page` 越界→400；`offset` 超出 `-128..127`→400 |
| POST | `/api/adjust/reset` | `{cell:0, page:int}` 或 `{cell:-1}` | `{ok, cleared}` | 坏 JSON→400；`page` 越界→400（`cell:-1` 表示清零全部） |

- `offsets` 保持 page-player 的**二维**形状（`cell_count` 恒为 1），便于将来多机扩展与代码复用。
- 「清零本页」在接口层用 `SetOffset(0, page, 0)` 实现，「清零全部」用 `ResetAll()`
  → **`PageAdjust` 类本身零改动**。
- 越界 `SetOffset` 在类内是静默忽略，接口层必须**显式校验**并返回 400（否则用户以为改了其实没改）。

### 3.2 前端：`calibrate.html` 重做为调整模式（手机优先）

```
┌─ 30 页行程标定 ────────────────────┐
│ ⚠ 30 页可用性判据：逐页点动，任意两页落到同一格 → 该机台不支持 30 页（改小总页数）
├─ 状态卡（4 格） ───────────────────┤
│ 当前页 3/30 │ 基础值 26 │ 偏移 +5 │ 实际值 31 │
├─ 微调行程（只改偏移，不翻页） ─────┤
│ [+10] [+5] [+1] │ [-1] [-5] [-10] │   （大按钮，≥44px）
├─ 翻页（真实翻页，用眼睛确认） ─────┤
│ [上页] [下页] [首页] [回零] │ 跳到第 [__] 页 [点动]
├─ 清零 ────────────────────────────┤
│ [清零本页偏移] [清零全部偏移]
├─ ▸ 高级：基础映射（折叠） ─────────┤
│ 原 30 行绝对行程值表格（初始值读**真实** values，不再公式猜；保存走 PUT /api/page-mapping）
└───────────────────────────────────┘
```

- **「当前页」用界面本地游标**（`curPage`）：上页/下页/跳页时更新并调 `POST /api/page/goto`；
  加载时读一次 `/api/lottery/status` 的 `current_page` 作为初值。**不依赖设备回读**（点动不写它）。
- 每次微调 → `PUT /api/adjust` → 用响应刷新状态卡（`value` 由服务端算，前端不自己推断钳位）。
- 翻页/点动失败（状态不允许、页码越界）→ 明确提示，不静默。
- 微调只在**未选中元素/无遮挡**的意义上与编辑页无关；按钮用共享 `app.css` 的 44px 触控规则。
- 「高级表格」默认折叠：避免误用；其初始值改读真实 `values`，**修掉原来的隐患**。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 回归污染设备偏移 | 测试前后**快照+逐页校验**（本轮刚立的铁律 §四-19）；api_verify 的 PUT 用例显式还原 |
| 前端自己算 `value` 与服务端不一致 | `value` 一律以 `PUT /api/adjust` 响应为准回填 |
| 微调误触把行程改飞 | 偏移钳位 `±128`；实际值钳位 `0..255`；界面显示"基础值/偏移/实际值"三项，异常一眼可见 |
| 30 页逐页调太久 | 提供跳页输入 + 首页/回零 |
