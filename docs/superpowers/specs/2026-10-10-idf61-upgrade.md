# 设计：ESP-IDF v5.5.4 → v6.1.0 升级（lucky-page）

> 日期：2026-10-10　|　状态：已评审
> 背景：用户要求把项目 IDF 基线升级为 6.1（机器已装 `~/.espressif/v6.1/esp-idf`，v6.1.0，
> esp32p4_demo 项目已用同一环境构建成功）。

## 1. 目标与非目标

**目标**：项目在 ESP-IDF v6.1.0 下编译通过（`bash scripts/build.sh s3` → `Project build complete`），
构建入口（build.sh / run_tests.py）统一指向 v6.1 工具链；不改变任何业务行为。

**非目标**：不在本次做真机烧录验证（设备未连接时）；不趁机升级 managed_components 版本
（除非 v6.1 下编译失败才升级 button）。

## 2. 环境事实（已核实）

| 项 | v5.5.4（旧） | v6.1.0（新） |
|---|---|---|
| IDF | `~/.espressif/v5.5.4/esp-idf` | `~/.espressif/v6.1/esp-idf` |
| Python venv | `tools/python/v5.5.4/venv` | `tools/python/v6.1/venv` |
| CMake | 3.30.2 | **4.0.3** |
| xtensa 工具链 | esp-14.2.0_20260121 | **esp-15.2.0_20251204**（GCC 15） |
| Ninja | venv 内 | **独立目录 `tools/ninja/1.12.1`** |
| OpenOCD | 20251215 | 20260703（仅调试用，PATH 顺手更新） |
| ROM ELFs | 20241011 | 20241011（不变，仅此一版本） |

## 3. 破坏性变更影响面（逐项核实过 v6.1 源码）

1. **`driver` 兼容组件缩水（唯一必须改代码的点）**：
   v6.1 `components/driver` 只剩 i2c / touch_sensor / twai；`esp_driver_gpio` 是其
   PRIV_REQUIRES（不传递头文件路径），且**完全不含 esp_driver_uart**。
   → `REQUIRES driver` 不再能解析 `driver/uart.h`。
   **修法**：组件依赖显式化——`driver` → `esp_driver_uart esp_driver_gpio`。
   源码 include 路径 `driver/uart.h`、`driver/gpio.h` **不变**
   （v6.1 中它们位于 `esp_driver_uart/include/driver/uart.h`、`esp_driver_gpio/include/driver/gpio.h`）。
   涉及三处：`main/CMakeLists.txt`、`components/dw_printer/CMakeLists.txt`、`test_apps/main/CMakeLists.txt`。
2. **API 兼容**（已 grep v6.1 头文件确认保留）：`httpd_uri_match_wildcard`/`uri_match_fn`、
   `esp_wifi_scan_*`、`esp_timer`、SPIFFS、NVS、`uart_param_config` 系列、LED 页面无关。
3. **GCC 14 → 15**：默认不 `-Werror`，新警告不阻断；若出现错误级告警再按需修。
4. **sdkconfig 迁移**：`CONFIG_IDF_INIT_VERSION="5.5.4"`，全量重建时 idf.py 自动迁移，
   废弃项打 warning，逐条确认无行为影响。
5. **managed_components**：`espressif/button 4.2.1` 自带 IDF 版本分支（≥5.3 走新 API），
   预期兼容；若编译失败则 `idf.py update-dependencies` 升级。`cmake_utilities` 为构建辅助，
   由依赖锁自动处理。
6. **dependencies.lock 记录的 IDF 版本**：fullclean 后重新生成。

## 4. 方案

1. `scripts/build.sh`：环境三行（IDF_PATH / IDF_PYTHON_ENV_PATH / PATH）切换到上表"新"列；
   `ESP_ROM_ELF_DIR` 不变。
2. 三个 CMakeLists 的 `driver` 依赖 → `esp_driver_uart esp_driver_gpio`。
3. `test_apps/run_tests.py`：ENV 同步切 v6.1，并把 cmake/ninja/工具链加入 PATH
   （v6.1 的 ninja 不在 venv 里）。
4. `bash scripts/build.sh s3 clean` 全量重建，迭代至通过；保留 `sdkconfig`（迁移而非重写，
   保住现场配置：WiFi/奖池/分区表等）。
5. 文档同步：AGENTS.md 框架行、根 CMakeLists.txt 基线注释。

## 5. 风险与回滚

- 风险：sdkconfig 废弃项导致行为差异（如 PSRAM/Flash 配置漂移）——构建日志逐条核对 warning。
- 风险：GCC 15 对指针/告警更严格——按报错逐个修复，不做大面积改动。
- 回滚：本项目未纳入 git；升级改动面小且清单明确（build.sh / run_tests.py / 三个
  CMakeLists / 两个 idf_component.yml / console_cmd.cc / printer_uart.cc / 三个头文件保护宏，
  详见评审记录），逐文件还原即回到 v5.5.4 基线（build 目录 fullclean 后重建）。

## 6. 验证标准

| 层级 | 标准 |
|---|---|
| 编译 | `bash scripts/build.sh s3` 输出 `Project build complete` |
| 产物 | `build-esp32s3/lucky-page.bin` 生成，分区表/SPIFFS 镜像步骤不缺 |
| 单测 | 设备连接时 `python3 test_apps/run_tests.py` 全 PASS（不连接则留待真机回归） |
