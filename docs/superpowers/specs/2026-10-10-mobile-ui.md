# 设计：小票编辑界面手机化改造（含全站移动端统一）

> 日期：2026-10-10　|　状态：已评审（用户已确认：属性面板用**底部抽屉**、范围为**6 个页面统一**）
> 关联：`specs/2026-09-29-lucky-page-design.md`（编辑器元素 minHeight 等既有约束）

## 1. 需求与范围

用户诉求：**小票编辑界面是 PC 布局，要优化为手机布局，方便手机操作**。经确认：
1. 手机端「元素属性」面板采用**底部抽屉**（点选元素即弹出，画布不被顶走）。
2. 范围**包含其余 5 个页面**，统一移动端体验（触控尺寸/输入框/安全区）。

**目标**：手机上不用横向滚动即可编辑小票、点选元素后属性面板立刻可及、按钮都可拇指点中；
桌面端布局与交互**保持现状不变**（含冒烟测试依赖的 `colw=14/lineh=22` 拖动量纲）。
**非目标**：不改后端接口与渲染逻辑；不改小票版式语义（列/行/背景层规则不动）。

## 2. 现状与实测痛点

| # | 痛点 | 证据 |
|---|---|---|
| P1 | 画布比手机屏宽 | 画布 = `colw(14px) × 列数` → 58mm **448px**、80mm **672px**；手机可用宽仅 ~332~362px → `#stage` 必须横向滚动 |
| P2 | 触屏拖拽与页面滚动打架 | `.el` 只有 `pointerdown`，无 `touch-action:none` → 手指拖动被浏览器判为滚动手势，元素拖不动或拖一半丢失 |
| P3 | 属性面板距画布过远 | `.layout` 在 ≤1000px 塌为单列，属性卡片排在**整个画布之后**（画布 canvas 模式可长达数十行）→ 点选元素后要长距离滚动才能编辑 |
| P4 | 按钮/输入框过小 | 按钮 `padding:6px 11px`+13px ≈ **28px 高**（远低于 44px 触控标准）；`button.mini` 更小 |
| P5 | iOS 聚焦自动放大 | 输入框 `font-size:13px` < 16px → iOS Safari 聚焦时整页放大错位 |
| P6 | 缺安全区适配 | 无 `viewport-fit=cover` / `env(safe-area-inset-*)`，刘海屏底部按钮被遮挡 |
| P7 | prizes 页 9 列表格溢出 | 表格固定宽度输入（64+70+70+90+130px…）≈ 500px+ → 手机上必然横向滚动，且每格仅 64px 难以点中 |

> P1~P6 集中在 `receipt.html`（唯一双栏布局页）；P7 在 `prizes.html`；
> 其余 3 页（index/logo/calibrate/wifi）主要是 P4/P5/P6 的共性问题。

## 3. 方案

### 3.1 共享样式表 `app.css`（避免 6 份重复 @media）

服务器已支持 `.css`（`web_server.cc:96` 设 `text/css`；`WebStaticDecide` 对存在的安全文件
直接服务，无需后端改动与白名单），故新增 `main/assets/spiffs_contents/app.css`，
**在每页内联 `<style>` 之后**引入（同优先级下后者覆盖，媒体查询按 ≤640px 生效）：

- 触控尺寸：`nav a, button, .ap, .psel div` 在手机端最小高度 **44px**、内边距放大
- `input, select, textarea` 手机端 **font-size:16px**（消除 iOS 聚焦缩放），`min-height:44px`
- 安全区：`body` 底部 `padding-bottom: calc(env(safe-area-inset-bottom) + …)`；固定元素用 `env()`
- 通用件：`.actbar`（底部固定操作栏）、`.sheet`（底部抽屉容器）、`.tbl-cards`（表格转卡片）

桌面端（>640px）规则全部不生效 → **PC 布局零影响**。

### 3.2 `receipt.html`（重点）

1. **画布适配缩放（消除横向滚动）**
   - 引入 `zoom` 状态：`colw = round(14*zoom)`、`lineh = round(22*zoom)`，字号同步 `13*zoom`。
   - `fitZoom = (可用宽) / (14*列数)`；手机端初始即 `fit`（上限 1，避免放大失真），
     桌面端初始 `zoom=1`（**保持冒烟测试的 28px=2列 / 22px=1行量纲**）。
   - 工具条加缩放组：`−` / `适应宽度` / `＋`（10%~100% 步进），`paint()` 末尾同步 `--colw/--lineh`。
   - 拖动换算天然正确：`startDrag` 已用全局 `colw`/`lineh`，缩放后无需改公式。
   - 手机端隐藏标尺 `#ruler`（省纵向空间，列位可从属性面板精确输入）。
2. **属性/参数底部抽屉**
   - 把右侧两张卡片（元素属性 + 插入参数）包进 `#panels`；手机端 `#panels` 变
     `position:fixed` 抽屉（`bottom:操作栏高`、`max-height:52vh`、内部滚动），
     加把手与「收起」按钮；桌面端 `#panels` 仍是右栏（`static`），DOM 与 JS 复用同一份 `#form` → 不产生双份逻辑。
   - **抽屉不得盖住正在编辑的元素**（真机反馈后补充，见 `reviews/2026-10-10-mobile-ui.md` 的修复节）：
     ① 只有**轻点**选中才弹抽屉，**拖动时不弹**（否则手指下就被盖一层）；
     ② 弹出后把选中元素**平滑滚到抽屉上方的可见带**内（`ensureSelectedVisible()`）；
     ③ 抽屉打开时 `.layout` 追加 `padding-bottom:52vh`，让最底部的元素也能滚上去。
3. **底部固定操作栏**：保存模板 / 刷新预览 / 打测试页 + 状态提示 `#msg` 在手机端固定在底部；
   保存为主动作。关闭抽屉后依然一键可及。
4. **触控加固**：`.el{touch-action:none;-webkit-touch-callout:none}`、`#stage{overscroll-behavior:contain}`；
   拖动中给元素加 `.dragging` 视觉反馈（放大/阴影），手指不遮挡：拖动时元素上移 6px 的
   视觉偏移不改数据。
5. **工具条重排**：＋元素按钮加大并可换行；「纸宽/版式类型/花边行数」归组；
   低频的「恢复出厂 / 全部重置」收进 `<details>`「更多」，减少误触。

### 3.3 `prizes.html`（P7）

≤640px 时表格转**卡片列表**：`thead/表头行隐藏`，每行卡片化，每个 `td` 左侧显示列名
（JS 模板加 `data-label`，CSS 用 `::before{content:attr(data-label)}`），输入框 `width:100%`。
桌面端仍为原表格。数据/接口不变（`data-f` 字段与保存逻辑不动）。

### 3.4 其余 4 页

接入 `app.css` 统一触控/输入框/安全区；`calibrate.html` 点动按钮加大；
`logo.html` 文件选择与按钮加大；`wifi.html` AP 行加大；`index.html` 抽奖按钮
`width:min(200px,58vw)` 适配窄屏，各页主要动作在手机端进 `.actbar`（仅 wifi/calibrate）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 改动误伤桌面布局/冒烟测试 | 所有新规则置于 `@media(max-width:640px)`；桌面 `zoom=1`；改完跑 `web_smoke.py`（桌面视口）回归 |
| 抽屉遮挡画布导致拖不到元素 | 抽屉 `max-height:52vh` + 可收起；画布区预留 `padding-bottom` |
| 缩放后拖动步长错 | 拖动公式统一用 `colw/lineh`（缩放后的真实值），并加手机视口断言 |
| iOS 100vh/安全区 | 抽屉用 `max-height` 而非 `100vh`；固定栏用 `env(safe-area-inset-bottom)` |
| prizes 卡片化丢字段 | 只改 CSS + `data-label`，`data-f`/保存逻辑零改动，跑冒烟回归 |
