## 一、原始需求（用户原话）

## 二、需求分解

### R1 项目命名

- **R1.1** 项目名 = **`lucky-page`**（中文：幸运翻页机）。
- **R1.2** 与基线 `page-player` 命名风格一致（同后缀、同语义域）。
- **R1.3** 目录名、CMake `project()` 名、组件前缀统一为 `lucky-page`。

### R2 单机翻页

- **R2.1** 只控制 **1 台**翻页设备，`cell_count` 恒为 `1`，代码层面断言并强制。
- **R2.2** 沿用 `page-player` 的 DMX512 输出路径（UART1 + TTL485，`GPIO17/18` + DE `GPIO4`）。
- **R2.3** 沿用 `PageMapping`（页码→DMX 行程）与 `PageAdjust`（逐页微调偏移）。
- **R2.4** **不包含**巡页、定时翻页、计数器、时钟模式（非目标）。
- **R2.5** **开机必须归零**（§设计 5.5）：翻页机是开环机构，无法回读物理位置，因此上电后必须驱动到第 0 页并等机械稳定（约 11~13 s），**归零完成前拒绝一切抽奖触发**。若中途断电，重启后一律重新归零（不持久化中间状态）。

### R3 按钮触发抽奖

- **R3.1** 按下按钮触发一次抽奖（沿用 `BUTTON_MODULE_GPIO`，高电平有效）。
- **R3.2** 抽奖进行中（翻页/打印）**忽略所有新触发**（单飞），并记录日志。
- **R3.3** 长按按钮 → 打印测试票（现场排障，不依赖网络）。
- **R3.4** 按钮回调内**禁止耗时操作**，只 `Application::Schedule()` 到主线程。

### R4 水果机随机翻页效果

- **R4.1** 视觉过程：**快速随机跳页 → 逐渐减速 → 擦边 → 弹跳 → 停稳**，总时长 **4.9~5.3 s**（默认 `min_hops=18`/`max_hops=20`，逐跳复算，见设计 §5.3 时序模型；可调参压到 3.1~3.4 s）。
- **R4.2** 跳页过程中**不得提前停在最终页**（保证"最后一下才落定"）。
- **R4.3** 步进间隔对齐 `MotionEngine` 的 40 ms tick，避免抖动；曲线为 ease-out。
- **R4.4** 整条动作序列**一次性下发**给 `MotionEngine`，**不阻塞**主循环。
- **R4.5** 落页结果必须与**售票面奖项 100% 一致**（先抽奖 → 再翻到该页；禁止先随机翻页再反查奖品）。
- **R4.6** 落定后**二次定位**（补发一次幂等的 `ActionPaging`），修正机械抖动/丢步。

### R5 奖品等级池（可配置）

- **R5.1** 奖品等级项包含：`level`（等级序号）、`page`（页码）、`weight`（**出现概率/权重**）、`quantity`（**投放数量**）、`remaining`（剩余）、`name`（等级名）、`note`（副标题）。
- **R5.2** 支持 **一等奖 / 二等奖 / 三等奖 / … / 谢谢参与** 等级结构，**最多 16 级**。
- **R5.3** **出现概率可配**：`weight` 为相对权重，实际概率 = `weight_i / Σ(未耗尽级 weight)`。
- **R5.4** **每级数量可配**：`quantity >= 1` 或 `-1`（不限量）。**必须跟踪库存**——抽中后 `remaining` 递减，归零则该级自动退出抽奖池（不得超发）。
- **R5.5** 每个 `page` 至多被一级占用（否则"停在某页"含义不唯一）；`level` 不得重复。
- **R5.6** 全部限量级耗尽时按 `depletion_policy` 处理：默认**回退到不限量兜底级**（保证机器不冷场）；可配为**拒绝开奖**（`out_of_prizes`）。
- **R5.7** 奖池配置非法时**拒绝生效**（返回中文错误原因），保留上一份有效配置。
- **R5.8** 三级兜底：`NVS 配置` → `NVS 备份` → `编译内建默认奖池`，**设备永远能开奖**。
- **R5.9** 库存变更持久化；断电方向为"**宁多发一个，不少发**"（扣减后立即落盘）。
- **R5.10** Web 端须显示**实时理论概率**（各级概率 + 合计），不得让商家把 `weight` 当百分比心算。

### R6 总页数（可配置）

- **R6.1** 总页数**可配置，默认 30 页**（= 可停靠的页数）。
- **R6.2** 改页数时，若奖池中存在 `page >= 新页数` 的级 → **拒绝保存**并提示具体页码。
- **R6.3** 开机 `kBoot` 必须硬断言 `PageMapping` 覆盖全部页且**各页行程值互不相同**；否则拒绝进入可开奖状态（防"永远停同一位"的静默故障）。

### R7 TTL 热敏打印机

- **R7.1** 通过 **UART2（`GPIO47` TX / `GPIO48` RX，按实物照片核定）** 驱动 TTL 热敏打印机。**`GPIO43/44` 是板上 `TX0/RX0`（接 USB-UART 桥），禁止占用。**
- **R7.2** 命令集 = **ESC/POS**，参考 `tft_displaye` 已验证的实现（`components/dw_printer`）。
- **R7.3** 打印内容：可选 Logo、商家名、标题、奖项名、奖品副标题、票号、时间、页码、校验码、领奖说明、二维码。
- **R7.4** **中文必须正确**：应用侧 UTF-8 → GBK 转码 + `ESC t 0` 设定代码页。
- **R7.5** 票号 `YYYYMMDD-NNNN`（当日流水，跨日归零）+ CRC16 校验码。
- **R7.6** 未中奖（`谢谢参与`）不打二维码，且使用独立的未中奖标题。
- **R7.7** 打印在**独立 FreeRTOS 任务**中执行，**不阻塞**翻页与界面。
- **R7.8** 打印机异常（拔线/断电）**不得卡死**设备，状态机必须回到 `kIdle`。
- **R7.9** 波特率、引脚、纸宽可通过配置/命令修改，**免重新烧录**。

### R7b 小票文案（可编辑）

- **R7b.1** 小票文案可在 Web 端编辑：商家名、中奖标题、未中奖标题、票头模板、票尾模板、领奖有效期。
- **R7b.2** 模板支持占位符：`{shop}` `{prize}` `{note}` `{ticket}` `{time}` `{page}` `{validity}` `{check}` `{title}` `{nl}`。
- **R7b.3** 排版按**显示宽度**（中文 2 列）计算；每行不得超过纸宽，超宽**安全折行**且不切断多字节字符。
- **R7b.4** 未知占位符原样保留并告警，不静默丢弃。
- **R7b.5** 提供**渲染预览**接口，所见即所得，降低现场试错成本。

### R7c 商家 Logo（可上传）

- **R7c.1** 可在 Web 端**上传商家 logo** 并打印在小票票头。
- **R7c.2** 图像转换（缩放/灰度/二值化/抖动）在**浏览器侧**完成；固件只接收 `LGO1` 头 + 1-bit 栅格，**零解码库**。
- **R7c.3** 支持 58 mm（384 dots）/ 80 mm（576 dots）纸宽；高度上限 256 dots。
- **R7c.4** 服务端严格校验（magic / 宽度为 8 倍数 / 高度上限 / **长度精确匹配**），非法返回 `400` 且不落盘。
- **R7c.5** 写入使用**临时文件 + rename**，避免断电留下半截 logo 导致长期乱码。
- **R7c.6** Logo 异常时**跳过 logo 继续打票**，绝不因装饰性内容导致整票失败。
- **R7c.7** `GS v 0` 栅格指令**必须分包**（每包 ≤ 24 行），否则撑爆发送缓冲。

### R7d Web 配置

- **R7d.1** REST 端点分三组：抽奖/状态、奖池/页数、文案/Logo（详见设计 §8.1）。
- **R7d.2** 前端 4 页：`index.html`（抽奖+状态，含**归零倒计时**）、`prizes.html`（分级奖池+概率+库存）、`receipt.html`（文案+预览）、`logo.html`（上传+二值化预览）。
- **R7d.3** 所有写操作走"**同步校验 → 通过才落库**"；失败返回 `400` + 中文原因，不污染运行中的配置。
- **R7d.4** 所有 handler 只解析 JSON 并 `Schedule()`，**业务逻辑在主线程执行**。

### R8 串口排障命令

- **R8.1** `draw` / `ptest` / `pstatus` / `pdump` / `prizes` / `gbtest <中文>`。
- **R8.2** `ptest` 必须走与真实开奖**同一条渲染路径**，便于现场核对中文/logo/二维码。

### R9 非功能需求

- **R9.1** 遵循 `page-player/AGENTS.md` 的 SOLID 与分层依赖规则（依赖单向向内）。
- **R9.2** 嵌入式约束：无动态内存用于实时路径；ISR 不做耗时操作。
- **R9.3** **测试先行**：纯逻辑模块（分级奖池抽取+库存、减速计划、GBK 转码、小票模板渲染、logo 头校验+分包、票号、二维码字节流）必须先写测试。
- **R9.4** 代码风格：Google C++、`.h/.cc`、`kPascalCase` 枚举、`snake_case_` 成员、注释用简体中文。
- **R9.5** 版本号与 `CMakeLists.txt` 的 `VERSION` 同 commit。
- **R9.6** **Logo 与文案属装饰性内容，绝不能阻断主功能**（打票）：异常一律降级跳过并告警。

## 四、明确不做（范围边界）

| 不做项 | 原因 |
|---|---|
| 多机/矩阵翻页 | 只控制 1 台 |
| 巡页 / 定时 / 计数器 / 时钟模式 | 与抽奖无关 |
| 语音 / 音频 / 蓝牙 / MCP / License | 非目标 |
| DMX 录制回放 / ArtNet 输入 | 非目标 |
| 出卡机联动（弹卡） | 后续需求（`page-player/reqs/req0033a`） |
| OTA 门户 | 非目标（**但保留 OTA 双槽分区**，便于后续原地升级） |
| 打印机缺纸/过热状态轮询 | v1 不做（未接打印机 RX） |
| 厂商预编译打印核心 `.a` | 二进制依赖 + Zbb 指令风险 |

## 五、用户已确认的决策（本轮）

| # | 问题 | 用户确认 | 落地 |

| C6 | 小票文案 | **可配置、内容可编辑** | 占位符模板 + Web 编辑 + 实时预览（R7b） |
| C7 | 商家 Logo | **可上传** | 浏览器侧转 1-bit 栅格，固件零解码库；异常降级不阻断打票（R7c） |
| C8 | 本轮交付 | **只做设计文档** | 已交付 spec + plan + reqs |
| C9 | 奖池默认值 | **默认可以** | 定为编译内建默认奖池：30 页 + 4 级（一等 1 / 二等 5 / 三等 30 / 谢谢参与不限量；权重 1:5:20:74） |
| C10 | 小票文案 | **默认可以** | 用内置默认模板；全部文案仍可在 `receipt.html` 编辑 |
| C11 | 出卡机联动（弹卡） | **不需要** | 明确列为非目标，**不加**任何 GPIO/串口触发 |
